# Requirements

> Status: **reference** (reviewed 5 Oct 2026). One row per requirement, with the way it is verified and where it stands. All numeric limits are **proposals**: each is confirmed, tightened or dropped after the first measurements.
> **Verif.:** T = automated test, M = measurement on hardware, I = inspection or analysis, D = a logged demonstration. **Status** says how far the project has got, honestly:
> *Verified (SIL)* = an automated test on the host or the virtual rig passes; *Verified (host, live)* = also exercised with real firmware instances on `vcan0`; *rig pending* = the software side is verified and the M part waits for the hardware
> (procedures in `docs/procedures/`); *Waits for …* = cannot be built or verified before that thing exists; *Partly built*, *Not built*, *Out of v1 scope* = as stated.
> The tests that verify each requirement are named in [`FAULT_MATRIX.md`](FAULT_MATRIX.md) (faults) and in the test files themselves (every test name says what it checks).
